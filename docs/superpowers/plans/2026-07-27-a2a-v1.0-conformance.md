# A2A v1.0 Conformance

Bring `src-tauri/src/a2a/` to A2A Protocol **v1.0** on the wire, per
`https://a2a-protocol.org/latest/specification/` (verified against
`docs/specification.md` and `specification/a2a.proto` in the `a2aproject/A2A` repo).

**Policy:** emit only v1.0 form; accept legacy forms on input during the
transition (spec §A.2: "Servers MAY accept both legacy and current request
message forms... Emit only current form in responses").

## Conformance gaps

| # | Gap | Spec ref | Current |
|---|---|---|---|
| 1 | Part discriminator | §A.2.1 | `{"type":"text",...}` — neither v1.0 nor legacy |
| 2 | `extendedAgentCard` placement | §A.2.2 | absent |
| 3 | Enum encoding (ProtoJSON) | §5.5 | `"completed"` / `"user"` |
| 4 | Missing task states | proto `TaskState` | no `INPUT_REQUIRED`, `AUTH_REQUIRED` |
| 5 | RPC method names | §9.1, §9.4 | `message/send`, `tasks/get`, `tasks/cancel` |
| 6 | AgentCard shape | §4.4.1 | no `supportedInterfaces`, no `securitySchemes` |
| 7 | `Message.messageId` | proto `Message` | not modeled (dropped on parse) |
| 8 | FilePart | proto `Part` | no variant |
| 9 | `SendMessageRequest.configuration` | §3.2.1 | not modeled |

## Step 1 — `types.rs`: Part (§A.2.1)

Replace the `#[serde(tag = "type")]` enum with a struct whose members *are* the
discriminator, matching proto `Part`'s `oneof content` + shared `filename` /
`mediaType` / `metadata`:

```rust
pub struct A2aPart {
    pub content: A2aPartContent,     // flattened
    pub filename: Option<String>,
    pub media_type: Option<String>,  // -> "mediaType"
    pub metadata: Option<Value>,
}
pub enum A2aPartContent { Text(String), Raw(String), Url(String), Data(Value) }
```

- **Serialize:** manual `impl Serialize` (or `#[serde(flatten)]` on an untagged
  inner enum) emitting exactly one of `text` / `raw` / `url` / `data`, plus
  `filename` / `mediaType` when set. No `kind`, no `type`.
- **Deserialize:** manual `impl<'de> Deserialize` over a `serde_json::Map` that
  probes in order:
  1. v1.0 — bare member `text` / `raw` / `url` / `data`;
  2. legacy v0.3.x — `kind: "text"|"file"|"data"`, unwrapping
     `file.{name,mimeType,fileWithBytes,fileWithUri}`;
  3. this repo's `type: "text"|"data"` form.
  Unknown/absent → `-32602` style error.
- Add helper ctors `A2aPart::text(s)` / `A2aPart::data(v)` so the ~15 existing
  construction sites in `adapter.rs`, `capabilities.rs`, `tasks.rs` become
  one-line changes rather than struct literals.
- Match sites (`adapter.rs:344,358`; `capabilities.rs:297,309`) switch on
  `part.content` instead of the enum directly.

## Step 2 — `types.rs`: enums (§5.5 ProtoJSON)

- `A2aTaskState`: rename serde reprs to `TASK_STATE_SUBMITTED` … and add
  `InputRequired` / `AuthRequired`. `is_terminal()` must treat both new states
  as **non**-terminal (spec calls them "interrupted").
- Add a custom `Deserialize` accepting the old lowercase names too.
- `A2aMessage.role`: `String` → `A2aRole` enum serializing `ROLE_USER` /
  `ROLE_AGENT`, deserializing those plus `user` / `agent` / `assistant`.
  Update the role comparisons in `adapter.rs:~310,~330` (`build_request_context`,
  `latest_user_text`) to match on the enum.

## Step 3 — `types.rs`: Message / Artifact

- `A2aMessage`: add `message_id: String` (required by proto; generate via
  `tasks::generate_task_id()` for agent-authored messages), plus optional
  `context_id`, `task_id`, `metadata`.
- `A2aArtifact`: drop the non-spec `index` field; add optional `metadata`.
  `description` stays. Adjust the 4 artifact construction sites.

## Step 4 — AgentCard (§4.4.1, §A.2.2)

New shape in `types.rs` + `adapter.rs::build_agent_card_with_skills`:

```json
{
  "name": "OmniLauncher",
  "description": "...",
  "version": "0.1.0",
  "supportedInterfaces": [
    {"url": "http://127.0.0.1:1423", "protocolBinding": "JSONRPC", "protocolVersion": "1.0"}
  ],
  "capabilities": {"streaming": false, "pushNotifications": false, "extendedAgentCard": false},
  "securitySchemes": {"bearer": {"httpAuthSecurityScheme": {"scheme": "Bearer"}}},
  "securityRequirements": [{"schemes": {"bearer": {"list": []}}}],
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"],
  "skills": [...]
}
```

- Delete `AgentAuthentication` and top-level `url`; `state_transition_history`
  is not in the v1.0 proto — drop it.
- `AgentSkill`: `description` and `tags` become required (non-`Option`);
  add optional `examples`, `inputModes`, `outputModes`. The non-spec
  `inputSchema` field is kept but moved under skill `metadata`-style handling
  only if `capability_to_agent_skill` needs it — otherwise dropped.
  Check `capabilities.rs::capability_to_agent_skill` and adjust.

## Step 5 — JSON-RPC methods (§9.1, §9.4)

In `jsonrpc.rs::dispatch`, match PascalCase primary + legacy alias:

| v1.0 | legacy alias accepted |
|---|---|
| `SendMessage` | `message/send` |
| `GetTask` | `tasks/get` |
| `CancelTask` | `tasks/cancel` |
| `SendStreamingMessage` | `message/sendSubscribe` | → `-32004` unsupported (unchanged) |

Add `ListTasks` → `handle_task_list` (already implemented in `adapter.rs`, just
unrouted today).

`SendMessageParams` → `SendMessageRequest` shape: `{message, configuration?,
metadata?, tenant?}`. Keep tolerant `#[serde(alias)]` for the current
`contextId` / `skillId` top-level params so existing callers still work;
read `message.contextId` first per spec.

Wrap the reply per proto `SendMessageResponse`: `{"task": {...}}` rather than a
bare Task. Same for `GetTask`/`CancelTask` — proto returns a bare `Task` for
those, so leave them unwrapped.

## Out of scope

Streaming (SSE `statusUpdate` / `artifactUpdate` envelopes), push notification
config methods, `ListTasks` pagination/filtering, and the `HTTP+JSON` binding.
`capabilities.streaming` / `pushNotifications` stay `false`, which is honest and
conformant. Noted here so a later change can pick them up.

## Compatibility note

Any client pinned to the current `{"type":"text"}` request form keeps working
(tolerant input). Any client *parsing* our responses for `"type"` will break —
that is the intended A.2.1 change. Worth a heads-up to omni-agent-hub.
