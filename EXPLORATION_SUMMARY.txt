================================================================================
CORE ARCHITECTURE INSIGHTS
================================================================================

1. PLUGIN SYSTEM (Most Important)
   - All functionality implemented as plugins implementing Plugin trait
   - Plugins have: keyword (optional), query(), tool_schema(), execute_tool()
   - 30+ plugins registered in lib.rs create_plugin_manager()
   - PluginManager handles routing, sorting (by score), limiting results

2. FRONTEND ARCHITECTURE
   - Dual mode: Launcher (fast search) vs AI Chat (Claude integration)
   - State: query, results, aiModeEnabled, conversationHistory, theme, settings
   - Dynamic window sizing (compact 56px → expanded 520px → AI 560px)
   - Markdown rendering with custom parser
   - Keyboard navigation (arrows, enter, escape)
   - 5 slash commands for quick access (/help, /new, /clear, etc.)

3. BACKEND ARCHITECTURE  
   - AppState manages: PluginManager, AiClient, Settings, ConversationContext, SkillManager
   - 10 Tauri commands: search, ai_query, execute_result, slash_preview, etc.
   - Async/await with Tokio runtime
   - Tauri IPC for frontend-backend communication
   - Global hotkey registration (Ctrl+Shift+O)
   - System tray icon for quick toggle

4. AI INTEGRATION
   - OpenAI-compatible API (Claude via Anthropic SDK)
   - Plugins provide tool schemas for Claude tool calling
   - Iterative tool execution loop (Claude → Tool → Claude → Response)
   - Conversation context persistence
   - Tool usage tracking for UI display

    tools_used?: [String],   // Which plugins were used
    isStreaming?: Boolean,   // Streaming indicator
  }

PLUGIN INTERFACE (Complete)
================================================================================

#[async_trait]
pub trait Plugin: Send + Sync {
  // Required methods:
  fn name(&self) -> &str;
  fn description(&self) -> &str;
  fn keyword(&self) -> Option<&str>;                    // e.g., "=" for calc
  async fn query(&self, q: &Query) -> Vec<QueryResult>; // Main search logic
  
  // Optional methods (defaults provided):
  fn tool_schema(&self) -> Option<serde_json::Value> { None }
  async fn execute_tool(&self, _args: serde_json::Value) -> String { String::new() }
}

Examples:
- CalculatorPlugin: keyword "=", evaluates math expressions
- WebSearchPlugin: keyword None, handles g/yt/gh/wiki prefixes
- BashExecPlugin: keyword ">", runs shell commands
- FileSearchPlugin: keyword "*", finds files by name

================================================================================
TAURI COMMANDS (Frontend ↔ Backend)
================================================================================

search(query: String) → Vec<QueryResult>
  Searches all plugins, returns top 10 results

ai_query(query: String) → AiResponse
  Sends query to Claude with tool schemas, handles tool calls, returns response

execute_result(result: QueryResult) → bool
  Executes action associated with result (open URL, run command, etc.)

slash_preview(query: String) → Vec<QueryResult>
  Special handling for / commands (/app, /find, /grep, /web, /kill, /clip, /calc)

get_settings() → AppSettings
  Loads current settings

save_settings_cmd(settings: AppSettings) → bool
  Persists settings and updates app state

list_models(base_url, api_key) → Vec<String>
  Fetches available models from AI provider endpoint

list_skills() → Vec<SkillInfo>
  Lists installed skills/plugins

reload_skills() → bool
  Reloads skill directory

install_skill(source: String) → String
  Installs skill from URL or path

set_window_geometry(height, ai_mode) → bool
  Updates window size/position (responsive to monitor)

clear_conversation() → bool
  Clears AI conversation history

================================================================================
QUERY FLOW (Step-by-step)
================================================================================

1. User types in input field
   → handleQueryChange() called

2. Frontend checks prefixes:
   - If "/" → Show slash suggestions (no backend call)
   - If "?" or "ai " → Switch to AI mode
   - Otherwise → Debounce 100ms

3. Frontend calls: invoke("search", {query})

4. Backend search() command:
   - Gets PluginManager from AppState
   - Calls pm.query_all(query)

5. PluginManager.query_all():
   - Iterate each plugin
   - Check if plugin.keyword() matches
   - Call plugin.query()
   - Collect results
   - Sort by score (descending)
   - Limit to top 10

6. Backend returns Vec<QueryResult>

7. Frontend receives results:
   - setResults(res)
   - ResultList renders items

8. User selects result:
   - Press Enter or Click
   - handleExecute(result)
   - Matches action_type:
     * "url" → Browser
     * "shell" → Command
     * "copy" → Clipboard
     * "open" → File manager
     * etc.

================================================================================
KEY PATTERNS & BEST PRACTICES
================================================================================

1. Plugin Registration:
   - Centralizes in lib.rs::create_plugin_manager()
   - Each plugin instantiated once

2. Async/Await:
   - All I/O is non-blocking (Tokio)
   - Trait methods use #[async_trait]

3. Tool Schemas:
   - Plugins provide JSON schemas
   - Claude uses them for tool calling
   - Reduces code duplication

4. State Management:
   - Frontend: React hooks (useState, useRef, useEffect)
   - Backend: Arc<Mutex<T>> for thread-safe shared state

5. Theme System:
   - Color palettes defined as constants
   - CSS-in-JS with inline styles
   - Conditional rendering based on theme state

6. Window Geometry:
   - Dynamic based on content
   - Responsive to monitor size/position
   - Centered on screen

7. Debouncing:
   - Search requests debounced 100ms
   - Prevents excessive backend calls

8. Error Handling:
   - Frontend: try/catch with user feedback
   - Backend: Result types, Option types
   - Graceful fallbacks
